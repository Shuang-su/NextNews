# Compressed SH in stable GPU pages — 2026-09-17

This batch extends the experimental encoded SOG stable-page renderer to retain SH1–3. Full Viewer acceptance remains incomplete. PLY and floating-point stable pages have not gained high-order SH support in this batch.

## Implementation

The per-Gaussian encoded reference packs a source-book slot, centroid label and source degree. Sorting continues to change draw addresses only. Higher coefficients remain an RGBA8UI centroid atlas with a per-source page table and scalar codebooks; they are not expanded into 192-byte float arrays per Gaussian. Mixed source degrees use their own books and labels. SH0 sources keep their existing base-color path.

The centroid atlas is allocated lazily at 64 MiB, with a 512 KiB mapping texture. Its 64 KiB pages use active-selection protection and LRU reuse. Capacity exhaustion retains the current scene and reports an error. Source data, books and mappings must all be ready before selection commit. Centroid, mapping and base uploads share the existing 4 MiB per-frame budget. Identical resident mapping rows are not uploaded again.

CPU page-cache accounting charges a shared SH source once within that cache. This does not yet constitute a global accounting ledger across independent caches or process memory measurements.

## Remaining acceptance

Exact same-camera Web comparisons; nonzero SH2/3 terms; repeated cancellation, cache pressure and context recreation; full floating-page SH; larger-scene memory and upload costs; 20-run performance gates. Native Huawei SH and tiled streaming remain separately unverified. No default renderer or budget was promoted based on this fixture.

A lifecycle audit also found and fixed a cross-path state hazard: entering an SH0 paged scene after a high-order single model could retain the old single-model SH binding. Paged draws now disable that binding before enabling their own per-source SH path. Phone background/foreground return preserved the three-plane colored view (`resumed.png`); this is not a surface-recreation stress test.

## Follow-up: nonzero higher bands and numerical GPU checks

The new `scripts/harmonyos/test_sh_gpu.py` compiles the production `ShShader` into a desktop OpenGL fragment harness and reads a float framebuffer. An independent real spherical harmonic oracle uses associated Legendre recurrence and angular normalization, rather than copying the shader's Cartesian polynomials. With the README Xcode override, Apple M3 Ultra passed **2,910 samples**, maximum absolute channel error **1.51479e-7**, tolerance 2e-5.

Coverage: float, single compressed and paged compressed adapters; all 15 higher coefficients nonzero; two independent scalar books; labels 0/63/64/1092/65535; reordered draw addresses; nonidentity centroid page mapping; SH0/1/2/3 display caps; both model-coordinate flip states; axial and oblique view directions. This checks shared GLSL on desktop hardware, not the phone's full vertex/render pipeline or same-camera Web visuals.

Reproduce:

```bash
DEVELOPER_DIR=/Applications/Xcode-27.0.0-beta.5.app/Contents/Developer python3 scripts/harmonyos/test_sh_gpu.py
# Use a fresh output directory and a Python installation with lossless WebP/Pillow:
python3 scripts/harmonyos/make_sh_stream_fixture.py /path/to/new-fixture --highest-band
```

`--highest-band` adds nonzero zonal terms at coefficient 1, 5 and 11 for the three respective source degrees. On the same Mate 80 Pro Max / API 26, these three planes rendered and changed directional colors after an orbit drag. Evidence: `high-bands-ready.png`, `high-bands-turned.png` under the local evidence directory above.

Twenty same-selection retries on that **768-Gaussian** phone fixture all reported three page hits and zero upload bytes; nearest-rank selection-to-display P95 was **7.45 ms**. Raw evidence: `high-bands-pages.log` and `high-bands-retries.json`. This is a residency regression, not a turn/LOD-selection benchmark and not evidence for the 2M/4M performance gates.

The audit also fixed silent loss of source SH metadata in floating stable pages: source SH is now preserved during parsing and unsupported high-order float pages are explicitly rejected with guidance to use encoded SOG pages or compatibility mode. Supporting floating-page SH remains unfinished; its lack of support must not be reported as an SH0-only source file.

## Follow-up: asynchronous failure display

The unsupported float-page test exposed a separate loading-state bug: native decoding had failed but the opening overlay continued to say “preparing”. Native errors now carry their scene request number through N-API; the loader captures that number when work is queued and suppresses errors from superseded jobs. The loading UI displays only matching errors, clears them when retry starts, and does not reopen the first-load overlay for later LOD failures. The SH limitation has a Chinese recovery message. Host regression checks cover current/stale/unowned errors, retry, and ready-state recovery.

Phone negative/recovery path passed after the fix: `failure-fixed.png`/`.json` show the Chinese failed state; switching the same session to encoded textures automatically retried and displayed all 768 Gaussians (`failure-recovered.png`/`.json`, request 2, display revision 2). The current signed HAP was rebuilt, installed and launched successfully. No repeated large-scene or full lifecycle acceptance is inferred from this check.
