# First physical-device run — 2026-09-14

Device: HUAWEI Mate 80 Pro Max. HDC reports API 26 Release. Application
source: commit 5071e30; no compatibility downgrade or global toolchain change.
The device reports OpenGL ES 3.2 / Maleoon 935. Native viewport: 1320×2623.

The official CLI generated the device debug profile in the ignored signing
copy. Signed HAP installation and EntryAbility launch succeeded. Signing
materials, device identifiers and account logs remain local and untracked.

The public 80,000-Gaussian PLY displays upright. A fixed ten-second orbit
recorded 780 successful EGL swaps in 10.00 seconds (78.0 submissions/s).
This counts render submissions/swaps, not independently measured display
presentations. It is one short USB-connected run, not a sustained thermal or
battery benchmark. Do not compare directly with different simulator viewports.

The driver exposes GPU query timing; the public sample reported 0.01 ms in one
snapshot. This raw value has not been independently validated against a hardware
profiler and is not evidence of device-wide GPU utilization.

The local SOG server is bound to Mac loopback and forwarded via HDC. The app
uses http://127.0.0.1:8768/scene.json. The connection requires the USB forwarding
and local server to remain available; this is not a hosted production service.

## Reproduce

With only the intended phone connected:

```bash
bash scripts/harmonyos/debug-build.sh
source scripts/harmonyos/env.sh
cd .local/signed-harmonyos/apps/harmonyos
devecocli run --skip-build --device '<phone serial>'
```

Run `bash scripts/harmonyos/serve_stream.sh` from the repository root for the
USB-forwarded data source. In the app use Model → Stream → Connect; open
Settings → Performance information → Measure 10 seconds for the fixed orbit.
The benchmark freezes the current resident selection and stops streaming, so
it does not include simultaneous streaming performance.

## Large-scene sample

The progressive SOG scene reached 2,000,000 resident Gaussians with 58/533
packages cached. The fixed orbit produced 335 successful swaps in 10.01 seconds
(33.5 submissions/s). One status sample reported 49.3 ms CPU sorting and
25.5 ms frame/swap wall time; these are snapshots, not aggregate distributions.
GPU query timing again reported 0.01 ms, so it should not be used as a bottleneck
conclusion without independent profiling.

After this test, process VmRSS was 605,948 KiB (about 592 MiB), and VmHWM was
851,832 KiB (about 832 MiB). These are process metrics, not total GPU memory.

The foreground roof is visible. The previously documented blurry environment
also remains on the phone, so it is not merely a simulator artifact. Web/native
visual parity and sustained performance acceptance are still open.

## Interaction smoke checks

CLI-injected viewport drag and double-tap mode switching ran on the phone;
the fly caption and joystick became visible. A joystick drag at speed 150 was
rejected by the CLI; retrying at 300 succeeded. This was an automation parameter
issue, not an observed application crash. No sustained manual touch ergonomics
or two-finger regression is claimed from this smoke check.

Home → EntryAbility relaunch preserved the public scene and returned successfully.
The phone was left on the upright public sample for manual use. USB streaming
remains available while the forwarding/server stay connected.
