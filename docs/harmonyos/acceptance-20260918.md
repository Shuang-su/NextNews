# SH0 版本真机验收 — 2026-09-18

2026-09-18 最新用户决定：停止研究 Spatial Recon。华为实现和已取得证据仅作历史记录，不再纳入后续开发与验收；后续范围为 C++ / OpenGL 对齐 MetaFlow / SuperSplat。


接续 `dd069b9`，OpenGL 按用户决定固定 SH0。本报告只把本次实际取得的证据列为通过，历史实现记录不能代替当前验收。OpenGL 完整 Viewer 发布验收尚未通过。

设备：HUAWEI Mate 80 Pro Max（SGT-AL10），API 26，Maleoon 935。使用现有 SDK / 已签名 HAP，包哈希见 [build.json](evidence/acceptance-20260918/build.json)。没有修改原始资源、线上配置、MetaFlow 参考工程或其他平台文件。

## 原生流式性能

同一华发/前海本地测试数据，533 个 SOG 均核验无 `shN`；固定 SH0、1320×2623、FOV 75°、原 `viewer-settings.json` 镜头。GPU 编码稳定页路径。20 次 yaw ±0.65 转向，先预热两次；连续运动单独运行 20 秒。未降低预算、LOD 或分辨率。

| 条件 | 次数 | 目标完整显示 P95 | 连续帧间隔 P95 | 状态 |
| --- | ---: | ---: | ---: | --- |
| 200 万 GPU 热缓存 | 20 | 332 ms | 33.401 ms | 差异：恢复超过 250 ms |
| 200 万仅文件缓存 | 20 | 3460 ms | 本条件未测 | 差异：超过 1500 ms |
| 400 万 GPU 热缓存 | 20 | 610 ms | 98.833 ms | 差异：超过 500 / 50 ms |
| 800 万 GPU 热缓存 | 20 | 1162 ms | 238.542 ms | 差异：实验档，不外推 |

三组 GPU 热缓存均为实际绘制预算数量、覆盖率 1、网络 payload 0、高斯页上传 0。文件缓存每次清空运行时页，重新解码上传至少 32×目标高斯数量字节，网络 payload 0。文件命中与 GPU 命中没有混算。连续运动仍允许预取及新页上传，因此“零上传”仅指记录的热缓存转向组。

200 万热缓存关联了全部 20 个提交版本，prepare P95 229.61 ms（包含排序），排序 P95 156.87 ms，提交到 EGL 显示 P95 283.15 ms。CPU 准备/排序是明确的优化方向；不能将这些百分位直接相加，也不能把 EGL swap 当成物理屏幕扫描时间。

数据：各目录的 `trials.csv`、`frames.csv`、`result.json`、`timeline.txt`、`memory.txt` 和截图保留逐次证据。内存是测试结束快照，不代表峰值或无泄漏。测试按顺序运行，没有随机化热状态，不能把新旧差值全部归因于某一次提交。

首次尝试缺失 HDC 8768 端口转发，页面加载失败；该次没有性能样本，不计入上表。恢复转发后的 `gpu-2m-retry` 才是有效组。尚无本轮 20 次真实网络冷启动数据，不用本地转发下载冒充 CDN 冷启动。

## 同手机 Web 对照

| 200 万预算，20 次 | 就绪 P95 | 连续帧间隔 P95 | 最后记录绘制数 |
| --- | ---: | ---: | ---: |
| 官方 SuperSplat v1.31.2 / `96f62515` | 294 ms | 169 ms | 1,997,529 |
| MetaFlow `a871786d` / PlayCanvas 2.21.3 | 302.3 ms | 171.7 ms | 2,009,695 |
| NextNews OpenGL SH0 | 332 ms | 33.401 ms | 2,000,000 |

两套 Web 均运行于同一手机 ArkWeb / Chromium 144 的 WebGL2，固定 1320×2623；关闭额外效果，MetaFlow 使用 `noreveal`。只在独立参考副本中加入固定分辨率与测量钩子，没有修改原始参考工程。来源与包哈希见 [reference.json](evidence/acceptance-20260918/reference.json)。

Web 使用引擎 `frame:ready` / loading=0 后再经过一次绘制，原生要求选中集合覆盖率 1、数量和提交版本都已显示；Web 缓存没有区分文件/CPU/GPU，层级分配和实际绘制数也不同。该表说明这组轨迹的观测差异，不是完整等价验收，也不能宣称所有场景原生更快。4/8M Web 对照尚未在此表覆盖。

第一次 MetaFlow 尝试命中了 ArkWeb 中旧的官方页面，无 8784 服务请求，已剔除。对照入口现明确选择 MetaFlow / SuperSplat，以不同端口和页面请求编号隔离页面缓存。有效 MetaFlow 组确认脚本和分块都来自 8784。

## 主机回归

25 个 ArkTS/配置/缓存/输入测试及 8 个原生测试组通过。原生核心、碰撞、网格、流缓存、图像、标注、调试及 SOG 测试输出已保留。524,598 个高斯的 SOG 与独立同数量 SH0 PLY 对照和损坏归档拒绝通过。

初次 sweep 两项失败已说明并修复调用/测试预期：LOD 需要真实 scene.json 参数及已编译比较器，补齐后 3443 叶节点 / 12 镜头预算组合一致；环绕测试仍断言已被用户要求移除的 `[0.05,20]` 场景相对缩放限制，现改验世界距离最小 0.01、无最大值和非法输入拒绝。SOG 首次自动调用缺少必需的两个文件参数，补齐后通过。原始失败日志保留，没有将失败输出改写为成功。

这些仅证明主机逻辑和数据数学，不证明手机画面、触摸设备或华为引擎等价。

## 视觉与华为核验

OpenGL 标注夹具截图已看到前景编号完整显示、后景编号减淡、半透明高斯前的编号部分透出，弹窗文本保持独立；离屏弹窗被约束到屏幕范围，相机后方标注不显示弹窗。初始截图处于开场阶段，不能拿它断言编号丢失。

同一夹具在华为页面仅见灰背景和 2D 标注；进入后台之前就没有显示三颗高斯，不能用恢复后的同样灰图证明恢复成功。真实模型与 tiled 核验在下方独立记录。华为不具备与 OpenGL 相同的标注深度实现，继续保留阻塞，不静默切换后端。

### 本次华为修复与复测

发现 `ModelBounds.ets` 新增标注夹具后，实验页仍使用 `SAMPLE_BOUNDS[index]`：公开按钮实际选到 Tripo，转换按钮实际选到公开模型，tiled 相机范围也取错。现按明确文件名查找，不再让夹具顺序改变按钮语义；已构建、签名、安装并实机确认公开入口显示 `public.ply` 人物。

修复版的同源 524,598 高斯对照（Rz180、单位缩放、配置镜头、FOV75）：

- OpenGL SOG 在等待开场结束后显示彩色场景及标注；初次 4 秒截图仍处开场，不能用于静态对照，最终重新等待 20 秒。
- Huawei SOG 显示几何但颜色灰褐，同数量 PLY 恢复彩色；几何轮廓和朝向相符，但背景和渲染结果仍有差异，不判像素等价。
- Huawei PLY 一次 Home→恢复后仍显示同一镜头内容。ROI `[100,500,1220,1650]` 的 8bit 平均绝对差 0.0414、P99=1；并非每个像素相同，也不代表压力生命周期通过。
- 修正范围后 tiled 调用返回节点，但初始和移动后仍无 `tile ready` 回调，画面没有整场模型；取消后可再加载公开人物。原生流式继续阻塞，不能把返回成功当作多块显示通过。

截图及筛选时间线：[spatial-fixed](evidence/acceptance-20260918/spatial-fixed)。`spatial-retry` 为修复前证据，不能替代最终结果。独立实验页验证不自动扩大为共用后端全部生命周期通过。

## 用户范围变更与最终回归

用户停止华为研究后，立即终止了共用 Viewer 脚本中尚未完成的后端回归，并重启回默认 OpenGL。已完成的华为截图和缺陷修正保留，不再追加试验。标注完整脚本在停止指令前已结束且通过；共用 Viewer 脚本被中断，不计为通过。后续仅继续 OpenGL 视觉、交互及性能收尾。

回归脚本 `verify_annotations.py` 和 `verify_viewer_common.py` 现默认仅验证 OpenGL，华为分支需要显式历史选项，避免后续常规验收再次自动进入已停止的路径。

停止华为分支后，纯 OpenGL 共用 Viewer 回归已重新完成：公开模型、10 个标注导航、播放/暂停、时间轴、Home→恢复、飞行游戏控件均通过脚本断言并留图。该结果不包含多指真实排列、所有物理输入或全画质像素对照。
